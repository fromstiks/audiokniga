# Сервер-агрегатор

Общий адрес для поиска: приложение спрашивает один сервер, сервер опрашивает
источники и отдаёт готовый список книг в едином формате.

```
GET  <base>/search?q=запрос      → список книг
GET  <base>/book?src=…&u=…       → одна книга со списком глав
```

## Нужен ли он вообще

Приложение и без сервера опрашивает все источники сразу — этим занимается
`ProviderRegistry`, а вкладки под строкой поиска показывают, кто что ответил.
Так что агрегатор не добавляет новой возможности, он переносит разбор с телефона
на сервер. Это имеет смысл, когда:

- разбор приходится часто править — правка на сервере не требует новой сборки APK;
- источников много и телефон не должен ходить в каждый сам;
- полезен общий кеш: одинаковые запросы не бьют по чужим сайтам повторно.

Если ничего из этого не про вас — сервер не нужен, добавляйте источники прямо
в приложении.

## Чего здесь нет

В коде нет ни одного конкретного сайта. `adapters/site.js` — универсальный
адаптер: он получает шаблон поиска и несколько CSS-селекторов из `sources.json`
и работает по ним. Какие каталоги туда вписать — решает владелец сервера, и он же
отвечает за то, что имеет право оттуда качать.

Готовыми включены только Internet Archive и LibriVox: открытые API и
общественное достояние. Они же служат проверкой, что сервер вообще работает —
пустой агрегатор невозможно отличить от сломанного.

## Развёртывание

**Важно про тариф.** Функции на бесплатном плане Spark не имеют исходящей сети к
чужим сайтам — им доступны только сервисы Google. Агрегатор без исходящих запросов
бессмыслен, поэтому нужен план **Blaze** (оплата по факту). У Blaze есть бесплатный
месячный порог, и личный поиск укладывается в него с большим запасом, но карту
привязать придётся.

```bash
npm install -g firebase-tools
firebase login

cd server
cp .firebaserc.example .firebaserc      # впишите свой project id
cd functions && npm install && cd ..

firebase deploy --only functions
```

После развёртывания консоль напечатает адрес функции — примерно такой:

```
https://europe-west1-ваш-проект.cloudfunctions.net/api
```

Проверьте его прямо в браузере: `…/api/search?q=чехов` должен вернуть JSON со
списком книг.

## Подключение к приложению

Меню → **Источники** → добавить источник:

```
Название: Мой агрегатор
Адрес:    https://europe-west1-ваш-проект.cloudfunctions.net/api/search?q={q}
```

Больше ничего настраивать не нужно: приложение узнаёт формат ответа само по
содержимому. Кнопка «Проверить» рядом с источником покажет, сколько книг и глав
он вернул.

## Свои источники

Правится `functions/sources.json`, затем `firebase deploy --only functions`.

Лента RSS или Atom — самый простой случай:

```json
{
  "id": "avtor-chtec",
  "name": "Авторские озвучки",
  "enabled": true,
  "url": "https://example.org/feed.xml"
}
```

Каталог на сайте описывается селекторами. Откройте страницу выдачи в браузере,
посмотрите разметку карточки книги и заполните поля:

```json
{
  "id": "catalog",
  "name": "Каталог",
  "enabled": true,
  "search_url": "https://example.org/?s={q}",
  "result": "article.book",
  "title": "h2 a",
  "link": "h2 a",
  "author": ".author",
  "cover": "img",
  "limit": 8
}
```

- `search_url` — адрес поиска, `{q}` подставляется на место запроса;
- `result` — селектор карточки книги в выдаче;
- `title`, `link`, `author`, `cover` — селекторы внутри карточки;
- `limit` — сколько страниц книг открывать за поиск. Каждая — отдельный запрос
  к сайту, поэтому число небольшое.

Со страницы книги файлы снимаются общим извлекателем (`lib/extract.js`): сначала
обходится DOM, потом ищутся адреса внутри скриптов — там слэши экранированы, и
без разворачивания такие ссылки не находятся. Селекторы для глав не нужны.

Ошибка в настройке не проглатывается: она приезжает в ответе поиска полем
`config_problems`.

## Формат ответа

Поиск:

```json
{
  "version": 1,
  "query": "чехов",
  "results": [
    {
      "id": "archive:chekhov-rasskazy",
      "title": "Рассказы",
      "author": "Антон Чехов",
      "cover_url": "https://…/cover.jpg",
      "source": "archive",
      "page_url": "https://archive.org/details/…",
      "book_url": "https://…/api/book?src=archive&u=chekhov-rasskazy",
      "chapters_count": 24
    }
  ],
  "sources": [{ "id": "archive", "name": "Internet Archive", "count": 7, "ms": 380 }],
  "config_problems": []
}
```

Главы в выдаче поиска не обязательны: приложение спросит их отдельно по
`book_url`, когда книгу откроют. Ответ на `book_url` — то же самое с полем
`chapters`:

```json
{
  "version": 1,
  "book": {
    "id": "archive:chekhov-rasskazy",
    "title": "Рассказы",
    "chapters": [
      { "index": 0, "title": "Хамелеон", "audio_url": "https://…/01.mp3", "duration": "0:12:40" }
    ]
  }
}
```

Разбор в приложении снисходительный: ключи ищутся среди синонимов
(`audio_url`, `url`, `file`, `src`…), длительность понимается и числом секунд,
и строкой `10:16:00`. Свой сервер можно писать на чём угодно — достаточно попасть
в этот формат примерно.

## Расходы и ограничения

- `maxInstances: 5` в `index.js` — потолок на случай, если адрес узнает кто-то ещё.
- Ответы кешируются на 5 минут: и внутри функции, и заголовком `Cache-Control`.
- У каждого источника свой крайний срок 9 секунд — один медленный сайт не держит
  весь поиск. Не успевшие попадают в `sources` с пометкой.
- Холодный старт добавляет к первому запросу секунду-две.
